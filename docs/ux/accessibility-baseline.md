# MAOS Accessibility Baseline

## Purpose

Define MVP accessibility expectations before frontend implementation.

## Keyboard Navigation

Interactive controls must be reachable and usable by keyboard. Modal, menu, dialog, and route focus behavior must be defined before implementation.

## Contrast

Text, controls, error states, disabled states, and status badges must meet accessible contrast targets appropriate for the MVP.

## Labels

Inputs, buttons, icon buttons, filters, tabs, dialogs, and file upload controls require accessible labels.

## Focus States

Visible focus states are required for interactive controls and must work in RTL and LTR layouts.

## Error States

Form errors must be programmatically associated with fields and must be visible without relying only on color.

## Form Accessibility

Forms must support keyboard submission, validation summaries where useful, required field indication, and safe denied states.

## Acceptance Criteria

| Criterion | Status |
|---|---|
| Keyboard navigation baseline is documented | Met |
| Contrast baseline is documented | Met |
| Label baseline is documented | Met |
| Focus state baseline is documented | Met |
| Error state baseline is documented | Met |
| Form accessibility baseline is documented | Met |
